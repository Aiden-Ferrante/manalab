## Problem

## Retro — 2026-08-11, cut same day

**What this actually bought.** Recoverability, and a starting point for the version
namespace. *"Did I finish anything this month?" → count the tags* is unanswerable
at zero tags, and every later cycle now has something to bump from.

**What went wrong, and it is the interesting part.** Two sessions were working in
this repo at once. Mid-way through, `HEAD` moved under me — `e41e6b2 fix(coverage):
unread text is not a parse` landed from the other one — so the tag ended up sitting
on a commit I had not verified. Re-verified in a clean clone; green. But the first
verification had been done by *stashing the other session's uncommitted work*,
which was a genuinely bad idea: had the pop failed, their work would have been
hidden in a stash they had no reason to look for.

**The rule that came out of it.** Verify a tag by cloning it, never by manipulating
a shared working tree. A clean clone is also the more honest test — it proves what a
fresh checkout does, which is the thing a tag is supposed to promise.

**Concepts worth keeping.** Bipartite matching for mana payment, because counting
sources per colour is wrong whenever duals exist. Common random numbers as variance
reduction. Both are general, not Magic-specific.

**What is next.** The open cycle is the card database, and its first child is not
the parser but the schema: all 886 null-text cards in the loaded table are two-part
names — split, DFC, adventure, flip — and 3,484 cards in the cached bulk file have
never been loaded at all. Extending the parser first would tune it on a corpus that
silently omits every multi-face card. Recorded as [[ADR 0006]].
